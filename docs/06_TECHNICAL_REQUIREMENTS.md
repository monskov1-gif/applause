# TECHNICAL REQUIREMENTS

## Платформа

Современный браузер на Windows/macOS/Linux; GitHub Pages; статическая
сборка без backend. Проверять Chrome, Firefox, Safari; мобильные
браузеры — если поддержка заявлена.

## Сравнение движков

**Godot 4:** проверить HTML5 export, renderer, WebGL,
SharedArrayBuffer/COOP/COEP при необходимости, потоки, аудио, мобильные
ограничения, размер билда и base path. **Unity:** проверить WebGL,
память, компрессию, MIME/content-encoding, мобильные ограничения, размер
и относительные пути. **Unreal Engine 5:** проверить реальный автономный
web export; Pixel Streaming не считать статическим экспортом, он требует
серверной инфраструктуры. **Web-native:** TypeScript + Phaser/PixiJS и
Three.js/Babylon.js; оценить стоимость собственных инструментов сцен,
диалогов, катсцен, ресурсов, камеры и коллизий. Проверить актуальные
официальные документы, не полагаться на старые статьи.

## Критерии сравнения

GitHub Pages compatibility; размер/время загрузки; производительность;
2D в 3D; камера, коллизии, свет и VFX; диалоги, выборы, сохранения,
катсцены и ритм-сцены; зрелость web export; поддержка и масштабирование.
Составить таблицу, рекомендацию, риски и стоимость миграции.

## Архитектура

Core/state/transitions/save; Narrative/dialogues/flags/localization;
Gameplay/movement/interactions/masks/camera/puzzles; Theater Hub;
отдельные Chapters; Presentation/UI/animation/VFX/cutscenes; Audio;
Asset pipeline. Не создавать абстракции ради абстракций.

## Сохранения

IndexedDB предпочтительнее для больших структур; localStorage — для
настроек. Обрабатывать повреждённые/устаревшие данные, версионировать
формат. Предупредить, что очистка браузерных данных может удалить
прогресс. Не хранить персональные данные и не отправлять наружу.

## Ассеты и GitHub Pages

Оптимизировать изображения, модели, текстуры и аудио; загружать главы по
необходимости; исключать дубли и исходники из production. Пути
чувствительны к регистру. GitHub Actions собирает и публикует
`dist/`/`build/`; настроить base path для repository subpath,
`index.html`, локальный запуск и диагностику. Не нужны секреты для
статической игры.

## Производительность и диагностика

Ориентир — 30–60 FPS на типичном ноутбуке, короткое первое открытие,
оптимизированные ассеты и отключаемые тяжёлые эффекты. Бюджеты
размера/памяти определить после прототипа. Нужны dev-логи, понятная
ошибка загрузки, debug-флаги, тест смены глав и сохранения после
обновления, отсутствие критических ошибок консоли.
