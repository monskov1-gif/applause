# MASTER INSTRUCTIONS FOR CLAUDE CODE

Ты разрабатываешь THE FINAL SHOW — авторскую браузерную 2.5D
story-driven adventure с театральной фантазией, сюрреалистической
комедией, жанровыми мирами, музыкальными сценами и детективной тайной.

## Платформа

Игра обязана запускаться в браузере и публиковаться на GitHub Pages. Это
статический хостинг: не требуй backend; не делай внешние API
обязательными; поддерживай repository subpath (`/repository-name/`);
используй корректные относительные пути; сохраняй прогресс локально в
IndexedDB/localStorage; не отправляй пользовательские данные наружу.

## Сравнение движков — обязательный первый этап

Сравни Godot 4 HTML5/Web export, Unity WebGL, Unreal Engine 5 и
web-native стек TypeScript + Phaser/PixiJS + Three.js/Babylon.js. При
необходимости предложи альтернативу. Проверь актуальную официальную
документацию и ограничения именно актуальных версий. Оцени: GitHub
Pages, размер/скорость загрузки, производительность ноутбуков и
мобильных браузеров, 2D-персонаж в 3D-пространстве,
камера/коллизии/свет/VFX, диалоги/катсцены/сохранения, ритм-сцены,
зрелость web export, трудоёмкость и масштабирование.

Отдельно: не выдавай Unreal Pixel Streaming за статическую браузерную
сборку — он требует серверной инфраструктуры. Для Godot проверь
renderer, HTML5 export, потоки/COOP-COEP при необходимости, мобильные
ограничения. Для Unity — WebGL, память, компрессию, MIME и размер билда.
Для web-native — стоимость самостоятельной реализации редакторских
инструментов и игровых систем.

Составь сравнительную таблицу, аргументированную рекомендацию, риски,
стоимость миграции и небольшой прототип, который подтвердит выбор. Не
выбирай движок заранее.

## Аудит до изменений

Изучи репозиторий, текущий движок, зависимости, сцены, ассеты, build
pipeline и GitHub Actions. Прочитай весь пакет. Определи существующие
системы, которые нельзя ломать, противоречия и вопросы. Не переписывай
рабочую архитектуру без доказанной необходимости.

## Не упрощай замысел без согласования

Не превращай игру в обычную плоскую VN; не заменяй исследование
статичными экранами; не делай механики декоративными заглушками; не
вырезай истории друзей или финальный мюзикл. Если функция слишком
дорогая, предложи варианты компромисса. Не меняй сюжетный канон
самостоятельно.

## Этапы

A. Discovery: аудит, чтение документов, сравнение движков, риски и
архитектурный план. Пока не писать игровую реализацию. B. Технический
прототип: одна комната театра, 2D-персонаж в 3D/2.5D, камера, коллизии,
взаимодействие, световой эффект, диалог/выбор, тест сохранения, запуск и
публикация на GitHub Pages. C. Vertical slice: законченный фрагмент от
пробуждения Вари до первой аномалии/перехода в жанровый мир. D.
Production: модульные системы и главы; после каждой главы тестировать
хаб, флаги, сохранения и производительность. E. Release: чистая сборка,
Pages, относительные пути, браузеры, ассеты, консоль,
производительность, доступность.

## Архитектура и качество

Разделяй Core/state/save, Narrative/dialogues/flags, Gameplay, Theater
Hub, Chapters, Presentation/UI/VFX/cutscenes, Audio и Asset pipeline.
Сюжет храни в редактируемых данных. У каждой главы отдельный модуль с
входами/выходами. Ассеты загружай по необходимости. Предусмотри экран
загрузки, паузу, настройки, историю диалогов и версионированные
сохранения. Не добавляй аналитику без разрешения. Проверяй регистр путей
для Linux/GitHub Pages. Пиши читаемый код, тестируй диалоговые
узлы/флаги/сохранения, не маскируй ошибки пустыми catch. Не говори, что
функция готова, пока не проверил её в браузере.

## Референсы и музыка

Для каждого референса укажи, что перенять и что не копировать. Сам факт
загрузки не означает разрешение на использование. Музыкальные треки
анализируй по настроению, темпу, инструментам, динамике и функции сцены;
не встраивай без лицензии. Финальная музыка — оригинальная или
лицензированная.

## Первый ответ Claude Code

Верни понимание игры, карту репозитория, таблицу движков, рекомендацию
для GitHub Pages, риски, вопросы и план прототипа с критериями успеха.
На этом этапе не пиши игровую реализацию.
